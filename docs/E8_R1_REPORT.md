기준: 2026-10-28, 초안 PR #8의 `6ce54758f00a669c9618d9a8cf7fe491c960950b` 후속 작업. 기존 E8 결론·반증·동결 자료는 해당 커밋 그대로 보존한다.

## 주장과 반증의 의미

| `claim_kind` | 주장하는 범위 관계 | 유효한 반증 |
|---|---|---|
| `EXACT_FAILURE_PREDICATE` | R ↔ F | FP 또는 FN |
| `SUFFICIENT_FAILURE_CONDITION` | R → F | FP |
| `NECESSARY_FAILURE_CONDITION` | F → R | FN |
| `EMPIRICAL_SEARCH_GUIDANCE` | 후보 순서·예산에 도움이 될 수 있다는 경험적 가설 | 별도 개발 배치의 비용·효용으로 판단 |

F는 지정 구현·domain·Oracle 계약·실패 계열의 관측이다. TP/FP/FN/TN은 규칙의 예측과 F의 대응이며 도구가 제품 결함을 오탐했다는 뜻이 아니다. 관측되지 않은 다른 실패 계열과 미정의 특징은 UNKNOWN이다. AND/OR/NOT은 세 값 논리를 사용하므로 NOT UNKNOWN도 UNKNOWN이다. Source에서 반증되지 않은 충분·필요조건은 전역 법칙이나 다른 구현의 동일 결함 보증이 아니다. 특히 필요조건을 만족했다고 실패라고 판정하지 않는다.

기존 정확 분류식은 일관된 계약이었다. R1은 그 반증을 지우지 않고 새로운 종류·의미 버전·표현·실패 계열·domain·구현/Oracle에 결속한 새 ID를 만든다. `derived_from`과 부모 archive 해시를 보존하고 모든 적격 관측을 새 의미로 재판정한다. `DiscoveryEngine.observe()`부터 archive·후보 선택·snapshot·CLI까지 공통 의미 판정을 사용한다.

## 상태·정보·실행 경계

`source_claim_status`, `source_validation_status`, `corroboration_status`, `target_applicability`, `transfer_validation_status`를 분리했다. 다른 정상 C의 반례는 전이 주장을 반박할 수 있지만 원 Source의 범위 관계를 자동으로 거짓으로 바꾸지 않는다. 같은 C의 모순 라벨도 C 상태만 불일치로 격리한다. 같은 독립 구현·Oracle의 양성·음성 대조가 없으면 기존 Gate B를 통과하지 못한다.

학습·새 Source 개발 검증은 Gate A이며 독립 C가 없어도 수행한다. 외적 전이는 Gate B이며 현재 C·적격 미소비 T가 없어 `NOT_EXECUTED_READINESS_BLOCKED`다. Source의 추가 입력은 입력 일반화 검증이고 독립 구현이나 외적 일반화가 아니다. 새 배치가 Source 규칙을 반박하면 부모 동결 archive를 보존한 새 세대에 반증을 추가한다. 경험적 규칙은 생존만으로 채택하지 않으며 실제 후보 변화·별도 새 Source 배치·사전 비용 기준에 연결된 효용 영수증이 필요하다. 효용은 실제로 실행한 새 guided 후보에서 첫 확인 반례가 나왔을 때만 검토하며, Native나 이미 알려진 입력 재생의 첫 발견은 규칙 효용으로 승격하지 않는다. 비교 배치에 연관된 효과이지 개별 규칙의 인과 효과가 아니다. 미소비 claim ID에는 효용을 확대하지 않고, 후보를 쓰지 않은 음성 비교도 빈 ID 목록으로 기록한다.

현재 R1 부분 의미는 stateless 계약에 한정한다. 기존 stateful 경로는 이전 의미 그대로 보존한다. 학습 동결 archive는63,604,940바이트, 새42개 검증 후 archive는72,789,151바이트로 기존 worker 전송 한도8,000,000바이트를 넘는다. 이 대형 archive의 현재 계획 경로는 신뢰한 host의 논리적 경계이며 해당 자료를 Docker worker에서 실행했다고 주장하지 않는다. 명시적 R1 snapshot은128MiB까지 허용하되 legacy snapshot 한도8MiB는 유지한다. 원시 Source·C·Target 입력과 정답·실행 로그는 공개 패키지에 포함하지 않는다.

## 실측 병목과 보완

동일한63MB 자료를 한 번씩 복원→Source gate로 처리한 cProfile 측정에서 변경 전22.664094초, 변경 후9.8220918초였다. 복원18.6108655→9.5135881초, gate3.9176298→0.1719932초였으며 두 번 모두 같은 파일 해시·receipt·1,664주장·205trial후보를 유지하고 Target·Oracle 호출은0이었다. 프로파일 오버헤드를 포함한 단일 자료의 전후 측정이며 통제된 연구 성능 비교나 일반적 속도 향상 주장이 아니다.

측정에서 deepcopy와 반복 snapshot이 대부분을 차지했다. 엄격한 저널 재생 중 버려질 중간 반환 snapshot을 만들지 않고 최종 전체 재생 비교·fork 부모 해시 검증을 유지했다. 허용된 캐시 예산을 초과해 즉시 퇴출될 항목의 불필요한 복사를 생략하고, Source gate는 내부 읽기 전용 상태를 보되 외부에는 선택한 claim의 복사본만 반환한다. 검증된 현재 receipt의 메모는 종류·의미 버전·domain·Oracle·저널에 결속하고 공개 의미 범위 변경을 거부한다. 권한이나 판정 캐시를 다른 의미로 재사용하지 않는다.
